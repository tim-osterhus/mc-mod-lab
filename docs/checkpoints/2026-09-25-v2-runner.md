Previous public checkpoint: `c7efa97` on `main`. This remains a **partial tooling
checkpoint**, not completion of the autonomous-playtesting-v2 spec and not an

## Testable now

- Strict schema v2, duplicate-key rejection, bounded steps and keyframes,
  unknown-action refusal, explicit `pass`/`fail`/`unsupported`/`not_run`.
- Prepared packaged-client verification: exact artifact hash, Fabric mod
  ID/version, unique matching JAR in an isolated profile's `mods`, fresh
  Fabric launch-log line, marked disposable save, selected Java process,
  authenticated loopback PID/port and game directory.
- World/player/screen/full-frame observations; four GUI actions; screen-class
  and world-name assertions. An exclusive per-profile control lease is
  released only after a confirmed exit. Screenshot review stays independent.
- Step-boundary working-set and private-byte samples for the declared
  workload PIDs. The sample is not a hard RAM cap or a measured peak between
  steps.
- Fixture copy refuses an active source `session.lock` and never carries the
  lock into the new save.

Run the current suite, validate the example contract, and inspect the package:

```text
python -m unittest discover -s tests -q
python lab.py validate scenario-v2 examples/scenario-v2.json --portable
python scripts/check_release.py
```

The example's all-zero artifact hash is intentionally non-runnable. For a
live run, use a reviewed real packaged JAR hash and an **independent**
profile/save/port/token. Do not attach to another task's client.
