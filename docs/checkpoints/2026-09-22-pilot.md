# Disposable-client pilot checkpoint

Observed with toolkit commit `b38ecca` and the locally hardened Minecraft Mod MCP v0.3.0 lab6 derivative in a Windows Minecraft 1.21.1 Fabric Mojmap development client. The derivative was not a published intermediary production JAR. This record excludes local identity, tokens, saves, logs, screenshots, and raw reports.

| Check | Observed result |
| --- | --- |
| Doctor | Passed against the selected Java PID's quoted `@argfile` launch, loopback listener, disposable world path/name, actual player name, and Creative mode. |
| Vanilla written-book control | `use_item` captured with exit code 0 and `BookViewScreen` as the after-screen class. The parent independently viewed the 1280x720 after-image and found the Control page readable. |
| Deliberately wrong screen | Expected screen differed from actual `CreativeModeInventoryScreen`; capture failed with exit code 1 and `after screen class does not match expectation`. |
| Unchanged Aura guide | `use_item` produced no screen (null), rather than the expected guide screen; capture failed with exit code 1 and the same screen-mismatch reason. This is a reproduced baseline defect, not a fix. |

The reports acknowledged exit from control mode after the scenarios. The client saved, quit, and exited with code 0; no Java game process remained. Doctor recorded a 1208 MiB selected-client working-set sample against a 3800 MiB scoped tool-group limit. Parent sampling of client plus monitor observed peak working set 1361.2 MiB and peak private memory 1885.9 MiB. The CLI's own working set was sampled separately, not synchronized to the helper peaks, so these figures are not a verified full-group peak or a low-memory guarantee.

The lab6 source patch is packaged separately from the observed runtime artifact. A clean rebuild from the pinned upstream source compiled, and its three patched Java sources matched the frozen lab6 sources apart from line endings. The rebuilt JAR has a distinct ZIP hash and has not itself been run. The pilot establishes one bounded control path and honest failure reporting, not guide parity, broader mod parity, or production-JAR compatibility.
